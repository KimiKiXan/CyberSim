## 1. Обзор

CyberSim — это высокопроизводительная исследовательская среда, в которой
локальная большая языковая модель (по умолчанию Qwen 2.5 14B Instruct)
играет роль автономного оператора наступательной безопасности. Модель рассуждает по строгой схеме ReAct
(Reasoning → Acting → Observing), выбирает инструмент из курируемого реестра,
наблюдает за потоковым выводом stdout/stderr порождённого подпроцесса и
адаптирует следующий шаг. Каждое действие проходит через песочницу, которая
принудительно соблюдает список авторизованных целей, заданный оператором.

Бэкенд на FastAPI / WebSocket размещает агента и инструменты. Клиент PyQt5
(нативное приложение Windows, тёмная тема) предоставляет операторскую
консоль: терминал реального времени, менеджер целей с импортом / экспортом
JSON и CSV, дашборд загрузки файлов и многоформатный генератор отчётов
(Markdown, PDF, JSON).

CyberSim предназначен только для образовательного использования в полностью
изолированных лабораторных сетях. Песочница отказывается воздействовать на
любую цель, не входящую в явный список разрешённых.

### Ключевые возможности

- Автономный ReAct-цикл с самостоятельной отладкой при ошибках инструментов.
- Восемь интегрированных инструментов пентеста: Nmap, Gobuster / dirsearch,
  Nuclei, SQLmap, Hydra, чистый Python DOM-анализатор, Metasploit RPC и
  модуль постэксплуатационного перечисления.
- Телеметрия реального времени по WebSocket от сервера к клиенту.
- Генерация отчётов в нескольких форматах с агрегацией CVSS и метриками
  успешности.
- Строгая песочница на основе белого списка.
- Модульная архитектура — каждый инструмент это один наследник BaseTool.

## 2. Архитектура

```
+----------------------------------+      +-----------------------------------+
|         Клиент PyQt5             |  WS  |          Бэкенд FastAPI           |
|  - Дашборд / цели / загрузки     | <==> |  - SessionManager                 |
|  - Терминал (stdout/stderr)      |  HTTP|  - OllamaManager                  |
|  - Превью / экспорт отчётов      | <==> |  - ReActAgent (цикл рассуждений)  |
+----------------------------------+      |  - ToolRegistry + SandboxGuard    |
                                          +------------------+----------------+
                                                             |
                                          +------------------+----------------+
                                          | Инструменты: nmap, gobuster,      |
                                          |   nuclei, sqlmap, hydra, web_dom, |
                                          |   msfrpc, post_exploit            |
                                          +-----------------------------------+
```

| Путь                       | Назначение                                                       |
|----------------------------|-------------------------------------------------------------------|

## 3. Системные требования

### Операционная система

- Windows 11 Pro (основная поддерживаемая платформа).
- Windows 10 (работает, не тестировалось в дипломных демонстрациях).
- Дистрибутивы Linux с Python 3.13 и Qt 5 (работает, не тестировалось).

### Программное обеспечение

| Компонент       | Версия             | Назначение                                |
|-----------------|--------------------|--------------------------------------------|
| Python          | 3.13+              | Среда исполнения                           |
| Ollama          | актуальная         | Локально размещает LLM                     |
| Nmap            | 7.94+              | Сетевая разведка                           |
| Gobuster        | 3.6+ (или dirsearch)| Перебор каталогов                          |
| Nuclei          | 3.2+               | Сканер уязвимостей                         |
| SQLmap          | 1.8+               | Аудит SQL-инъекций                         |
| Hydra           | 9.5+               | Перебор аутентификации по протоколам       |
| Metasploit RPC  | 6.4+ (опционально) | Интеграция с эксплойт-фреймворком          |

### Аппаратное обеспечение

- Рекомендуется 16 ГБ ОЗУ (CPU-вариант с Qwen 2.5 7B потребляет ~6 ГБ).
- Для GPU-инференса: видеокарта NVIDIA с 12+ ГБ VRAM. Эталонное железо —
  RTX 4080 Super (16 ГБ): она запускает Qwen 2.5 14B Q5_K_M целиком на
  GPU со скоростью ~50 токенов/сек.
- 20 ГБ свободного места на диске для модели и промежуточных данных.

### Сеть

- Изолированная лабораторная подсеть. CyberSim никогда не должен быть
  направлен в публичный интернет без проверки границ оператором.

## 4. Установка

### 4.1 Установить Python 3.13

Скачайте установщик с <https://www.python.org/downloads/> и включите опцию
«Add Python to PATH». Проверка:

```powershell
py -3.13 --version
```

### 4.2 Установить Ollama

Скачайте установщик для Windows с <https://ollama.com/download>. После
установки запустите демон:

```powershell
ollama serve
```

(В стандартной установке Windows демон запускается автоматически при входе.)

Загрузите модель по умолчанию (под RTX 4080 Super, 16 ГБ VRAM):

```powershell
ollama pull qwen2.5:14b-instruct-q5_K_M
```

Облегчённый запасной вариант для CPU:

```powershell
ollama pull qwen2.5:7b-instruct
```

CyberSim попытается автоматически подтянуть модель при первом запуске,
если её нет в локальном кеше.

Проверка:

```powershell
ollama list
```

### 4.3 Установить пентест-инструменты

Восемь инструментов CyberSim делятся на две группы по способу установки:

| Тип             | Инструменты                                  | Как ставить                                  |
|-----------------|----------------------------------------------|----------------------------------------------|
| **Python pip**  | `sqlmap`, `dirsearch`, `pymetasploit3`, `paramiko`, `python-nmap`, `python-libnmap`, `beautifulsoup4`, `lxml` | `pip install -r requirements.txt` (см. 4.4) |
| **Нативные CLI**| `nmap`, `nuclei`, `gobuster`, `hydra`        | системный установщик (см. ниже)              |

CyberSim деградирует мягко — отсутствующий нативный бинарник просто заставит
соответствующий инструмент вернуть `not_installed` агенту; остальное
продолжит работать.

#### Автоматический установщик нативных бинарников (Windows)

В каталоге [`scripts/`](../scripts/install_pentest_tools.ps1) лежит
PowerShell-скрипт. Запустите его в PowerShell **с правами администратора**:

```powershell
.\scripts\install_pentest_tools.ps1
```

Он установит Chocolatey (если его нет), затем `nmap`, `nuclei` и
`gobuster`, и выведет таблицу — какие CLI теперь видно в PATH.

Можно ставить только подмножество:

```powershell
.\scripts\install_pentest_tools.ps1 -Only nmap,nuclei
```

#### Ручная установка по инструментам

| Инструмент   | Подсказка установки для Windows                                  |
|--------------|------------------------------------------------------------------|
| nmap         | `choco install nmap` или <https://nmap.org/download.html>        |
| gobuster     | `choco install gobuster` или <https://github.com/OJ/gobuster/releases> |
| nuclei       | `choco install nuclei` или <https://github.com/projectdiscovery/nuclei/releases> |
| hydra        | WSL (Kali): `sudo apt install hydra` (нативного пакета Choco нет)|
| metasploit   | <https://www.metasploit.com/download> (msfrpcd в комплекте)       |

### 4.4 Клонирование проекта и установка зависимостей Python

```powershell
cd G:\Diploma
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install -r requirements.txt
```

Одна команда устанавливает:

* Веб-стек (`fastapi`, `uvicorn`, `httpx`, `websockets`, …).
* LLM-клиент (`ollama`).
* PyQt5 десктоп-клиент и тёмную тему.
* **Восемь Python-помощников пентест-инструментов** (`sqlmap`,
  `dirsearch`, `pymetasploit3`, `paramiko`, `python-nmap`,
  `python-libnmap`, `beautifulsoup4`, `lxml`).
* Стек отчётов (`reportlab`, `python-docx`, `markdown`, `jinja2`).

### 4.5 Проверка установки

```powershell
python -c "import server, client, tools, agent_logic; print('imports OK')"
```

## 5. Настройка

CyberSim читает конфигурацию из переменных окружения. Значения по умолчанию
подходят для односерверного лабораторного стенда. Скопируйте `.env.example`
в `.env` и отредактируйте либо экспортируйте переменные в своей оболочке.

### 5.1 Настройки Ollama

| Переменная                | По умолчанию                       | Описание                                       |
|---------------------------|------------------------------------|-------------------------------------------------|
| `OLLAMA_HOST`             | `http://127.0.0.1:11434`           | Конечная точка HTTP Ollama                      |
| `OLLAMA_MODEL`            | `qwen2.5:14b-instruct-q5_K_M`      | Основной тег LLM (Qwen 2.5 14B Instruct)        |
| `OLLAMA_FALLBACK_MODEL`   | `qwen2.5:7b-instruct`              | Резерв, если основной тег отсутствует           |
| `OLLAMA_TEMPERATURE`      | `0.1`                              | Температура (низкая → строгий JSON)             |
| `OLLAMA_TOP_P`            | `0.9`                              | Параметр top-p (nucleus sampling)               |
| `OLLAMA_NUM_CTX`          | `16384`                            | Контекстное окно в токенах                       |
| `OLLAMA_TIMEOUT`          | `180`                              | Таймаут запросов, секунды                       |
| `OLLAMA_KEEP_ALIVE`       | `60m`                              | Сколько Ollama удерживает модель в VRAM         |
| `OLLAMA_FLASH_ATTENTION`  | `1`                                | Включает Flash-Attention на поддерживаемых GPU  |

### 5.2 Настройки сервера

| Переменная           | По умолчанию   | Описание                                       |
|----------------------|----------------|------------------------------------------------|
| `CYBERSIM_HOST`      | `localhost`  | Адрес привязки FastAPI (VPN-хост оператора)     |
| `CYBERSIM_PORT`      | `4899`         | Порт привязки FastAPI                           |
| `CYBERSIM_RELOAD`    | `false`        | Установите `true` для авто-перезагрузки Uvicorn |

### 5.3 Настройки агента

| Переменная                | По умолчанию | Описание                                       |
|---------------------------|--------------|------------------------------------------------|
| `AGENT_MAX_ITERATIONS`    | `40`         | Жёсткий лимит итераций ReAct в сессии          |
| `AGENT_REACT_PAUSE`       | `0.0`        | Опциональная пауза между итерациями (отладка)  |

### 5.4 Настройки Metasploit RPC (опционально)

| Переменная           | По умолчанию   | Описание                                       |
|----------------------|----------------|------------------------------------------------|
| `MSFRPC_HOST`        | `127.0.0.1`    | Хост msfrpcd                                   |
| `MSFRPC_PORT`        | `55553`        | TCP-порт msfrpcd                               |
| `MSFRPC_USER`        | `msf`          | Имя пользователя msfrpcd                       |
| `MSFRPC_PASSWORD`    | _(не задано)_  | Без значения инструмент msf даёт NOT_INSTALLED |
| `MSFRPC_SSL`         | `true`         | Использовать TLS для msfrpcd                   |

Запуск msfrpcd в отдельном терминале:

```bash
msfrpcd -P <пароль> -S -a 127.0.0.1
```

### 5.5 Тонкая настройка системного промпта

Идентичность агента, миссия и предохранители прописаны в файле
`config/system_prompt.md`. Отредактируйте файл и перезапустите сервер —
никакие изменения в коде не требуются.

### 5.6 Рекомендуемые модели по оборудованию

По умолчанию используется `qwen2.5:14b-instruct-q5_K_M` — модель подобрана
под RTX 4080 Super (16 ГБ VRAM). Выберите другой тег, если ваше железо
отличается:

| Оборудование                       | Рекомендуемая `OLLAMA_MODEL`                | VRAM    | Скорость   |
|------------------------------------|---------------------------------------------|---------|------------|
| RTX 4080 Super / 4090 (16-24 ГБ)   | `qwen2.5:14b-instruct-q5_K_M` *(по умолчанию)* | ~10 ГБ  | 45-65 t/s  |
| RTX 4090 / A6000 (24+ ГБ)          | `qwen2.5:32b-instruct-q4_K_S`               | ~19 ГБ  | 18-25 t/s  |
| RTX 4060 / 4070 (8-12 ГБ)          | `qwen2.5:14b-instruct-q4_K_M`               | ~8 ГБ   | 25-40 t/s  |
| Только CPU / без GPU               | `qwen2.5:7b-instruct`                       | RAM     | 8-15 t/s   |
| Диплом требует IBM Granite         | `granite3.2-dense:8b`                       | ~8 ГБ   | 25-50 t/s  |

Смена — один экспорт:

```powershell
$env:OLLAMA_MODEL = "qwen2.5:32b-instruct-q4_K_S"
```

Системный промпт не зависит от модели, других правок не потребуется.


## 7. Подключение клиента к серверу

По умолчанию клиент ищет сервер по адресу `localhost:4899` — это
VPN-присвоенный хост оператора (стиль Radmin VPN / Hamachi, подсеть
26.x.x.x). Чтобы указать другой адрес, экспортируйте переменные окружения
перед запуском клиента:

```powershell
$env:CYBERSIM_HOST = "localhost"
$env:CYBERSIM_PORT = "4899"
.\run_client.bat
```

Клиент использует HTTP для управляющего трафика (запуск сессии, список
отчётов, загрузка файлов) и WebSocket для потока событий реального времени:

```
HTTP  : http://localhost:4899/api/...
WS    : ws://localhost:4899/ws/sessions/<идентификатор-сессии>
```

### Устранение проблем подключения

1. Откройте в браузере `http://<host>:4899/health` — должен вернуться JSON.
2. Откройте Брандмауэр Защитника Windows и разрешите входящий TCP 4899.
3. Если клиент сообщает «server unreachable», изучите лог сервера; чаще
   всего причина — недоступность Ollama.
4. Команда `netstat -an | findstr 4899` подтверждает, что сервер слушает.

## 8. Эксплуатация фреймворка

Клиент CyberSim группирует операторскую деятельность по трём областям:
Дашборд, Терминал реального времени и Сессии / Отчёт.

### 8.1 Сформулировать задачу

В Дашборде заполните поле **Attack Objective** чётким описанием того, чего
должен достичь автономный агент. Примеры:

> «Просканируй веб-стек на http://lab.local, перечисли пути, проверь
> найденные параметры на SQL-инъекции и сформируй отчёт с рекомендациями».

> «Найди службы на 10.10.10.0/24, сосредоточься на хостах с открытым
> портом 445, определи версию ОС и проверь SMB-уязвимости».

### 8.2 Авторизовать цели

Добавьте цели в панель **Authorized Targets**:

- Одиночный IP — `10.10.10.5`
- Подсеть CIDR — `10.10.10.0/24`
- URL — `http://lab.local/admin`
- Имя хоста — `vulnbox.lab`

Список можно импортировать из JSON или CSV (см. `data/targets_sample.json`
и `data/targets_sample.csv` для ожидаемой структуры).

При пустом списке любой вызов инструмента будет отклонён.

### 8.3 Загрузить пользовательские полезные нагрузки (опционально)

В панели Дашборда **Scripts / Exploits / Wordlists** можно загрузить
собственные словари, скрипты или пейлоады эксплойтов. Агент сможет
ссылаться на них в аргументах инструмента (например,
`wordlist=./uploads/custom.txt`).

### 8.4 Запустить сессию

Нажмите **Launch ReAct Session**. Клиент переключится на Терминал
реального времени, откроет WebSocket к серверу и начнёт стримить события:

- `session_start` — задача и область действий оператора.
- `llm_thought` — рассуждение модели за этот ход.
- `tool_call` — выбранный инструмент и проверенные аргументы.
- `tool_stream` — построчный stdout/stderr подпроцесса.
- `tool_result` — структурированный итог возвращён агенту.
- `metrics` — итерации, вызовы инструментов, латентность, блокировки.
- `final_answer` — финальный отчёт агента (markdown).
- `session_end` — терминирующее событие.

### 8.5 Просмотреть сессию

Перейдите на вкладку **Sessions**, чтобы увидеть прошлые атаки, их
состояние и количество итераций. Выберите сессию и нажмите **Open
Terminal**, чтобы воспроизвести её лог событий, либо **Build Report** для
формирования и экспорта отчёта.

### 8.6 Экспортировать отчёт

На вкладке **Report** выберите формат (Markdown, PDF или JSON), нажмите
**Build** для компиляции и **Download**, чтобы сохранить файл.

## 9. Справочник реестра инструментов

Все инструменты используют общий контракт параметров в стиле JSON-схемы.
Полный каталог становится доступен LLM в начале каждой сессии.

### 9.0 Сводная инвентаризация

| Инструмент            | Бэкенд                                  | Способ установки                                       |
|-----------------------|----------------------------------------|--------------------------------------------------------|
| `nmap_scan`           | CLI `nmap`                             | `choco install nmap` или установщик                    |
| `dir_brute`           | CLI `gobuster` / пакет `dirsearch`     | `choco install gobuster` / `pip install dirsearch`     |
| `vuln_scan`           | CLI `nuclei`                           | `choco install nuclei`                                 |
| `sqlmap_audit`        | `sqlmap` (Python-пакет с CLI)          | `pip install sqlmap` (есть в `requirements.txt`)       |
| `auth_bruteforce`     | CLI `hydra`                            | WSL / Kali / cygwin                                    |

## 10. Справочник протокола ReAct

Каждый ход LLM должен заканчиваться ровно одним JSON-объектом на последней
строке:

```json
{
  "thought": "Nmap нашёл порт 80 — следующий шаг: перебор веб-путей.",
  "action": "tool",
  "tool": "dir_brute",
  "arguments": {"target": "http://10.10.10.5/", "threads": 30}
}
```

Завершение работы:

```json
{
  "thought": "Все проверки выполнены.",
  "action": "finish",
  "final_answer": "## Находки\n- Высокая угроза: ..."
}
```

Фреймворк возвращает следующее наблюдение в виде пользовательского хода:

```
Observation:
[nmap_scan :: ok] (2.3s)
nmap service scan of 10.10.10.5: 1 host(s), 3 open port(s) ...
```

Если модель выдала некорректный JSON, фреймворк:

1. Извлекает последний сбалансированный `{...}` фрагмент.
2. Если и это невалидно — просит модель повторить со строгим JSON.
3. Прерывает работу после `json_retry_limit` ошибок подряд.

## 12. Модель песочницы и авторизации

### 12.1 Белый список

`SandboxGuard.set_targets` пересобирает список разрешённых целей при
каждой сессии:

- Одиночные IP (`10.10.10.5`).
- Подсети CIDR (`10.10.10.0/24`).
- Имена хостов (`vulnbox.lab`).
- URL — извлекается хост (`http://lab.local/admin/` → `lab.local`).

### 12.2 Принудительное соблюдение

Каждый инструмент в `ToolSchema.target_fields` объявляет поля аргументов,
содержащие цели. Реестр преобразует значение в строку хоста, пытается его
разрешить через DNS и проверяет, входит ли результат в белый список.

- Пустой список — любой вызов отклоняется.
- Цель вне области — реестр возвращает `ToolStatus.BLOCKED` и публикует
  событие `sandbox_block`, чтобы LLM мог адаптироваться.

### 12.3 Запрещённые действия

Системный промпт явно запрещает:

- Воздействие на хосты вне белого списка.
- Эксфильтрацию данных за пределы лаборатории.
- Деструктивные пейлоады (вайперы, шифровальщики, руткиты-персистенты).
- Затопляющие DoS-атаки.

## 13. Генерация отчётов

Класс `server.report_generator.ReportGenerator` создаёт:

- **Markdown** — для документации, GitHub и быстрого чтения.
- **PDF** — операторского уровня, через ReportLab. Содержит таблицы с
  метриками и находками.
- **JSON** — полные машиночитаемые данные сессии.

### 13.1 Агрегируемые метрики

- Сумма вызовов инструментов: всего, успешных, с ошибками, заблокированных.
- Коэффициент успешности (успех / всего).
- Количество находок (с уровнем серьёзности).
- Максимальный и средний CVSS-балл.

### 13.2 Источники находок

- Срабатывания `nuclei` (id шаблона, серьёзность, CVSS, CVE).
- Подтверждённые SQLmap инъекции.
- Учётные данные, найденные Hydra.
- Сессии, открытые Metasploit (трактуются как находки уровня critical).

## 14. Устранение неполадок

| Симптом                                       | Вероятная причина и решение                                                                |
|----------------------------------------------|--------------------------------------------------------------------------------------------|
| «server unreachable» в клиенте                | Сервер не запущен или слушает другой адрес/порт. Проверьте лог `run_server.bat`.            |
| Лог сервера: «Ollama chat failed: ConnectError»| Демон Ollama не запущен либо `OLLAMA_HOST` указан неверно.                                  |
| Инструмент возвращает `NOT_INSTALLED`         | Соответствующий CLI отсутствует в PATH. Установите или пропустите.                          |
| Инструмент возвращает `BLOCKED`               | Цель не в белом списке. Добавьте её в панель Targets.                                       |
| Hydra: «no password list provided»            | Установите SecLists или укажите `pass_list` явно.                                            |
| msf_exploit возвращает `NOT_INSTALLED`        | `msfrpcd` не запущен, либо `MSFRPC_PASSWORD` не задан, либо нет `pymetasploit3`.            |
| Падение клиента «No module named PyQt5»       | Активируйте `.venv` и выполните `pip install -r requirements.txt`.                          |
| Цикл ReAct не завершается                     | Увеличьте `AGENT_MAX_ITERATIONS` или уточните задачу, чтобы критерии успеха были ясны.      |

## 15. Безопасность и этика

CyberSim — это **исследовательский и образовательный инструмент**.
Неправильное использование почти в любой юрисдикции является нарушением
законов о компьютерных преступлениях. На операторе лежат следующие
обязанности:

- Поддерживать изолированную лабораторную сеть.
- Иметь письменное разрешение на каждую загружаемую цель.
- Никогда не отключать песочницу в продакшн-окружении.
- Считать сгенерированные отчёты конфиденциальными — они могут содержать
  свидетельства эксплуатации уязвимостей.

## 16. Часто задаваемые вопросы

**В. Можно ли использовать другую LLM?**
О. Да. Задайте `OLLAMA_MODEL` в любой другой совместимой с инструментами
модели, размещённой в Ollama. Протокол ReAct не зависит от модели.
По умолчанию CyberSim поставляется с `qwen2.5:14b-instruct-q5_K_M`
(оптимально для RTX 4080 Super, 16 ГБ VRAM) и `qwen2.5:7b-instruct` в
качестве облегчённого варианта для CPU. Другие проверенные опции:
`llama3.1:8b`, `mistral-nemo:12b`, `granite3.2-dense:8b`.

**В. Как добавить новый инструмент?**
О. Создайте наследника `BaseTool`, объявите `ToolSchema`, реализуйте
`async def run(...)`, затем зарегистрируйте его в
`tools/__init__.py::build_default_registry`.

**В. CyberSim работает без интернета?**
О. Да — Ollama и все инструменты пентеста выполняются локально. Единственный
внешний трафик — это запросы самих пентест-инструментов к целям, которые вы
авторизуете.

**В. Как настроить поведение агента?**
О. Отредактируйте `config/system_prompt.md` (миссия, тон, предохранители)
и переменные окружения из раздела 5 (температура, контекст, лимит итераций).

**В. Можно ли экспортировать лог терминала?**
О. Да. Можно скопировать его из окна клиента или запросить JSON-отчёт — он
содержит каждое выпущенное событие.

## 17. Глоссарий

- **ReAct-цикл** — Reasoning → Acting → Observing; шаблон промптинга, в
  котором модель чередует рассуждения «вслух» и вызовы инструментов.
- **Реестр инструментов** — таблица исполнимых возможностей, доступных
  LLM, с JSON-схемой и метаданными песочницы.
- **Песочница** — компонент, принудительно соблюдающий белый список
  целей перед каждым вызовом инструмента.
- **CVSS** — Common Vulnerability Scoring System; стандартизованная
  метрика серьёзности, используемая в агрегации отчёта.
- **msfrpcd** — RPC-демон Metasploit, позволяющий удалённо управлять
  фреймворком по MessagePack RPC.
- **WebSocket-телеметрия** — низколатентный канал от бэкенда FastAPI к
  клиенту PyQt5.
